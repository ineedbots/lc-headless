# Script coverage reference

Optional behavioral coverage is tracked in [#62](https://github.com/ineedbots/lc-headless/issues/62),
which retains the migrated candidate-file table. This page preserves the saved snapshot and runtime-spec
instructions for the embedded stdlib, `src/Script/Stdlib/`. Script tests live in
`tests/Stdlib/`, and [Building.md](../Building.md#stdlib-script-coverage) describes the report these figures come from.
The figures are a snapshot: rerun the report rather than trusting them once tests have moved on.

**Saved snapshot (2026-11-05):** 76,822 of 78,503 executable lines (97.86%). All 436 files meet the
95% line-coverage floor; 1,681 lines remain uncovered. Generated by the full traced Debug run at
`build/windows-script-coverage/script-coverage/summary.json` (810 registered tests, all passing).

The report includes the parity findings fixes and native WordPack market reply regression. Later dragon/KQ
scenario additions passed focused Debug and Release runs; these bot scripts are outside the stdlib trace.
Cache-dependent tests skipped in the default suite were validated separately against revisions 225, 274 and 289;
those separate checks are not claimed as part of this traced report. Hidden `[Slow]` tests and scripts under
`scripts/` are not measured.

The coverage command and CI fail when any embedded stdlib file falls below 95%, using unrounded counts.
The old phase 17 runtime-spec backlog is complete as a coverage-floor task: specs now exercise quest actions,
failed prerequisites, interrupted combat, pocket recovery, journal boundaries and bank-first provisioning.
Remaining work is optional behavioral coverage; meeting the floor does not prove
that every upstream scenario has been ported.

## Writing a runtime spec

1. Put it in `tests/Stdlib/rs2b0t/quests/test_<quest>_<area>_runtime.py`. New files are picked up without a rebuild.
2. Build the world from `Scene` in `tests/Stdlib/rs2b0t/spec.py`, which fakes the pack, worn items, locs, NPCs, ground
   items, messages, chat, walking and the clock. A failed `delay_until` costs its whole timeout, so a leg's own deadlines
   expire as they do live.
3. Take each leg through its success and each of its failures, asserting on the outcome rather than only running the
   lines. `test_touristtrap_legs_runtime.py` and `test_legends_trials_runtime.py` are the models to follow.
4. Run the spec alone, then lint it:

   ```sh
   build/windows-script-coverage/Debug/Rs2004HeadlessTests.exe "rs2b0t's ported Python tests pass" -c test_<name>.py
   python -I tools/port/lint.py tests/Stdlib/rs2b0t/quests/test_<name>.py
   ```

To see one spec's coverage without a full run, set `RS2004_SCRIPT_COVERAGE_DIR` to an empty folder for that command, and
compare the JSON profiles it writes with `build/windows-script-coverage/script-coverage/manifest.json`.

Two pocketpy traps catch these specs:

- A closure captures an enclosing local when it's defined. A sibling function defined later is a `NameError`, and
  rebinding a local afterwards isn't seen, so define callees first and build effects in a helper for each object.
- Default arguments must be literals, so `stage=STAGE.STARTED` won't load.

## Known findings

The two findings from the earlier snapshot are fixed, with behavioral regressions:

- Grand Tree returns its newest cached journal stage when a stale recognized page is read; quest-list reset
  behavior is retained (`test_grandtree_state_runtime.py`).
- Tourist Trap's two unreachable `leave_camp` branches after `safe_recovery_route` were removed. Both camp
  floors still choose shared safe recovery at both affected stages (`test_defs_touristtrap.py`).

Some of what remains can't be reached by a test at all. `elementalworkshop/workshop.py` lines 129–130 and 657 and
`chompybird/hunt.py` lines 109–110 and 160 are guards on states the lines before them rule out, so 100% isn't the goal
for every file.
